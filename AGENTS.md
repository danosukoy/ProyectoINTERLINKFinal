# AGENTS.md — ProyectoINTERLINKFinal

## Project type
- Unity 6 (6000.3.8f1) C# project, three assemblies: `Game.Data` → `Game.Gameplay` → `Game.UI` (one-directional refs, enforced via asmdef)
- Universal Render Pipeline (URP)
- Platform: macOS (darwin)

## How to work
- **No CLI build/test/lint commands** — all work is done inside the Unity Editor. Open the project in Unity to compile, test, or run.
- There is no CI pipeline, no pre-commit hooks, no custom scripts.
- `.gitignore.txt` exists at root but is **not** named `.gitignore` — Unity generated files may be tracked if not renamed.

## Architecture

### Entry / persistent managers
- `EOSManager` — singleton, `DontDestroyOnLoad`, initializes Epic Online Services on `Awake()`. Must exist in the first loaded scene.
- `MenuManager` — handles scene switching via `SceneManager.LoadScene(int)`.
- `PlayerDataManager` — persists player data across scenes.

### Scenes (load order not enforced, but logical flow)
`StartMenu` → `SampleScene` (main gameplay) → `InventoryMenu`, `PerkMenu`, `WeaponMenu`

### Script boundaries (enforced by asmdef: `Game.Data` → `Game.Gameplay` → `Game.UI`)
| Directory | Assembly | Responsibility |
|---|---|---|
| `Assets/Scripts/Data/` | `Game.Data` | Pure data: `ItemDefinition`, `WeaponDefinition`, `WeaponRegistry/Runtime`, `RecoilProfile`, `SwayBobProfile`, `SkillInfo/Registry`, `GameModeDefinition`. No behaviour deps. |
| `Assets/Scripts/Player/` | `Game.Gameplay` | `PlayerController` (façade + orchestration), `PlayerLocomotion` (move/look), `PlayerCombat` (weapons/net/FX), `PlayerSmoothMovement`, `GroundCheck`, `PlayerUI`, `IRecargaUI` |
| `Assets/Scripts/Damage/`, `FX/` | `Game.Gameplay` | `Health` (server-authoritative), `HitboxZones`, `FXPool`, `Trazadora` |
| `Assets/Scripts/GameModes/` | `Game.Gameplay` | `GameModeManager` (FFA: countdown/scores/respawn), `GameModeDefinition` lives in Data |
| `Assets/Scripts/SteamScript/` | `Game.Gameplay` | `SteamManager`, `SteamLobbyManager`, `SteamP2PTransport`, `ClientNetworkTransform`, lobby avatars |
| `Assets/Scripts/Lobby/`, root managers | `Game.Gameplay` | `LobbyMatchController`, `LobbyArmeriaController`, `MapVoteManager`, `PlayerDataManager`, `MatchCountdownUI`, `SoloMatchController` |
| `Assets/Scripts/UI/` | `Game.UI` | All menus/HUD: armería (`ArmeriaUI/Tabs`, `WeaponButton`, `SkillButton`), `MapVoteUI/Station`, `GameModeHUD`, scoreboards, `MenuManager`, `InventoryManager` |

### Key conventions
- Scripts use Spanish comments and variable names (e.g., `puntos`, `velocidadMovimiento`, `enTransicion`). **Do not rename existing Spanish identifiers** without asking.
- `PlayerController` is a façade: `PlayerLocomotion.TickLocal/TickFixed` (move/look) + `PlayerCombat.TickLocal` (shoot/reload/switch). Cross-system talk goes through the façade, never direct component poking.
- UI never does global `GameObject.Find`: `ArmeriaUI` injects refs into buttons at creation; scene lookups are type-based (`FindFirstObjectByType`) and cached. `PlayerController.Todos/PorCliente` replaces per-frame scans.
- Gameplay never references UI types: UI self-bootstraps via `RuntimeInitializeOnLoadMethod` + static events (e.g. `MapVoteManager.AlSolicitarAbrirPanel`).
- Weapons are runtime state (`WeaponRuntime`) built from immutable `WeaponDefinition` assets; server owns ammo (`PlayerCombat.SyncAmmo`).

## EOS (Epic Online Services)
- Credentials (`productId`, `sandboxId`, `deploymentId`, `clientId`, `clientSecret`) are set via **Inspector** on `EOSManager`. Not stored in code.
- macOS requires `EOSMacHelper` / `EOSMacLoader` for native library loading.
- Related managers: `EOSAuthManager`, `EOSLobbyManager`, `EOSRelayManager`, `EOSSessionManager`, `EOSLeaderboardManager`.

## Gotchas
- `Library/`, `Temp/`, `obj/`, `UserSettings/` are gitignored — do not commit. Scene and prefab edits are safe.
- `.csproj` and `.sln` files are auto-generated by Unity — do not edit or commit manually.
- EOS credentials are **not** in source control — if EOS features fail to initialize, check Inspector fields on `EOSManager`.
